## 推荐简历条目

可以根据你的实际完成内容选择 3 到 4 条：

- 使用 FastAPI、SQLAlchemy 2.0 和 Pydantic 设计多用户任务管理 REST API，实现项目与任务 CRUD、分页、搜索、状态筛选及项目统计。
- 基于 OAuth2 Password Flow 和 JWT 实现登录鉴权，使用 scrypt 加盐哈希存储密码，并通过依赖注入统一校验资源所有权，防止跨用户越权访问。

## 面试讲解结构

用 60 秒说明项目时，可以按这个顺序：

1. 背景：很多任务管理示例只做 CRUD，无法体现后端工程能力。
2. 目标：构建一个多用户、数据隔离、可测试、可部署的任务管理 API。
3. 方案：FastAPI 路由层负责协议，SQLAlchemy 负责持久化，依赖注入处理身份和权限。
4. 难点：统一用户隔离、JWT 生命周期、数据库枚举兼容和测试环境隔离。
5. 结果：12 个测试通过，本地 SQLite 可运行，Docker 可切换 PostgreSQL，CI 自动检查。

## 高频追问

### JWT 和 Session 有什么区别？

JWT 把签名后的用户身份放进 token，服务端不保存会话；Session 通常在服务端保存状态，浏览器只保存 session id。JWT 适合水平扩展，但注销、权限即时失效和 token 吊销更复杂。

### 为什么密码使用 scrypt，不直接 SHA-256？

普通 SHA-256 速度太快，攻击者可以用 GPU 高速尝试密码。scrypt 是刻意消耗内存和 CPU 的密码哈希函数，并为每次密码生成随机 salt，能显著提高离线暴力破解成本。

### 为什么跨用户访问返回 404，而不是 403？

对于私有资源，404 不暴露“该 ID 是否存在”。这能减少资源枚举信息泄露，同时让统一权限逻辑更简单。

### 为什么列表接口要分页？

数据量增大后一次性返回全部记录会造成数据库扫描、网络传输和前端渲染压力。分页把资源消耗限制在固定上限，本项目单页最多返回 100 条。

### 当前项目还缺什么？

可以说出真实边界：自动建表适合本地和演示，生产迁移应接入 Alembic；JWT 目前没有 refresh token 和黑名单；统计查询规模变大后可以对常用过滤字段增加组合索引或缓存。

主动承认边界比声称“完全生产可用”更可信。
